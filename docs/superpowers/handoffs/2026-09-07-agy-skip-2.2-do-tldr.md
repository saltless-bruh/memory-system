1. GATHERING INLINE LINKS INTO A ## Cross-References SECTION CHANGES NOTHING.

I ran your proposal through the real ingest path on a page shaped like

Zero difference. The reason is the mechanism you are relying on: a section
whose heading is in _LINK_SECTION_NAMES has its pure-wikilink lines stripped,
which leaves that section with an empty body, and an empty section is skipped
entirely. Meanwhile `metadata.wikilinks` is extracted from the whole document,
so the inline links were already captured before you touched anything.

So the gathered section is written, stripped, and dropped. It costs 111 page
edits and buys nothing for retrieval.

That ordering matters: every one of those pages flips from failing to passing

And unlike the renames, this one is real for retrieval. scout/wiki_ingest.py
makes the ## TL;DR section **chunk 0** of the indexed page. It is scored first
against every query and it carries the page's identity. A page with a sharp
TL;DR is found by the question a person actually asks; a page without one is
found by whichever fragment happens to match.

So the bar is not "a TL;DR heading exists". It is: does this sentence contain
the words someone would type when they want this page? A TL;DR that restates
the title tells the retriever nothing it did not already have from the title.

does not say enough to compress, that page goes to wiki/_contract-exceptions.md
with one line on why, and you move on. That file does not exist yet; create it
in the batch where you first need it.

You identified 64 pages with no links at all earlier. Expect a comparable
number here that have no summarisable content. A long exception list is a
correct outcome and I will not treat it as underperformance. One invented
sentence is a failure, and it is invisible in review, which is exactly why it
is the rule.

Insert it as the first ## section, before whatever the page currently opens
with, so it precedes everything else in reading order.
