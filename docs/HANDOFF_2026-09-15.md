## 4 · Decisions already made — do not relitigate

All recorded in `REMEDIATION_PLAN.md` with reasoning. Summary:

- **One MCP server**, named **`snpmemory`**. The local stdio server is deleted.
- **Tools carry a domain prefix in the middle**: `snpmemory_wiki_search`. Not
  bare — `{server}_{tool}` is a convention, **not a collision boundary** (SEP-986).
- **Delete the CLI's identity as a product**, not its code. 26 commands become:
  7 MCP tools · 5 CI checks · 4 skills · 3 operator-deferred · 2 client-setup ·
  6 dropped.
- **CI runs a container**, after consolidating the 28 `scripts/`. Free checks
  (`verify-vault`, `verify-secrets`) block a push; expensive ones
  (`verify-addresses`, `verify-groundedness`) run weekly.
- **Skills ship their own tooling**, archify-style — `bin/` inside the skill,
  relative paths, no install.
- **`wiki_verify` is draft-only, content-in.** Whole-vault health is CI's job.
- **Vault layout stays; the linter's contract is wrong.** The contract becomes a
  *rule* — control files plus "every directory is lowercase" — not a list.
- **SARIF + a Postgres table** for CI results. OpenTelemetry considered and
  rejected (Release Candidate, wrong question, needs a collector).
- **Glossary + a lint rule** for synonym drift. A glossary without enforcement decays.

Still open and needing the owner: **A2** — self-hosted embeddings, or written
acceptance that vault text egresses to Google?

## 6 · The pattern that explains most of the defects

Three separate defects share one cause, recorded as register entry 45b:

- **#52** — the sparse arm returned nothing for 35 of 40 queries. Every test passed.
- **#59** — all four `verify_vault` tests monkeypatch the function holding the bug.
- **#65** — a test *asserts* the duplicate-tool-name configuration is correct.

Each checked **the shape a thing declares**, never **the result it produces**.
None was found by a test. They were found by measuring output, by control-testing
with a deliberately wrong input, and by the owner asking *"where does it actually
read from?"*

This is why `REMEDIATION_PLAN.md` will not mark anything `VERIFIED` on a green
result. **A fix must be watched failing before it is watched passing.**

## 7 · Things that will bite you

| | |
|---|---|
| `snpmemory verify-vault` | **Inert to every input.** Same output from the vault, from `/tmp`, from anywhere. Do not trust it. `verify-addresses` is affected too. |
| `snpmemory read` | Works, but is **cwd-sensitive**. Run it inside the vault, not the system repo. I misdiagnosed this as broken once. |
| `wiki_search` | **Never returns empty.** An out-of-corpus question still gets 5 confident-looking pages. Honesty comes from the read step. |
| `snpmemory install-agent` | Refuses a non-existent target. `mkdir -p` first. |
| `verify-groundedness` | Times out at 90 s with no output. Judge route unproven. |
| `plan-articles` | Fine on Markdown, **hangs on PDF** — vision extraction, connection refused. |
| `raw/` in `source_uri` | Means **two different trees**. 2 documents are searchable but not readable. |
